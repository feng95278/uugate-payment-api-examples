# USDT / USDC 回调处理：从验签到业务完成

[UUGate 收款回调文档](https://open.uugate.com/developers/payin-callback.html) · [English reference](https://open.uugate.com/developers/en-US/payin-callback.html)

回调签名正确，只证明请求体与认证凭据匹配；它不意味着可以跳过订单归属、金额、状态和重复通知的检查。

## 1. 保留原始请求体

在 JSON 解析或字段重排前保留原始 body。读取 `x-callback-timestamp`、`x-callback-nonce`、`x-callback-signature`，并使用创建原订单时的 API Key 校验 `timestamp.nonce.rawBody` 的 HMAC-SHA256。不要把 API Key 写入日志，也不要将接收服务只配置为“当前最新 Key”而丢失旧订单所需凭据。

完整签名与示例见[签名说明](https://open.uugate.com/developers/signing.html)。本仓库的离线演示只验证 HMAC，不实现接收服务。

## 2. 区分技术重复与业务重复

- 时间戳校验：按正式文档和接收端策略检查允许的时间窗口，处理好服务器时钟。
- 重放防护：对已处理的通知标识建立持久化记录，避免同一请求再次产生副作用。
- 订单幂等：即使平台重试产生新的 timestamp 或 nonce，同一个已完成订单仍只能交付一次。

因此，仅在进程内保存一个 nonce 集合不能保证业务幂等；服务重启或多个实例都可能破坏这类临时去重。

## 3. 核对订单事实

对照自己的订单记录，核对平台订单号、商户归属、客户订单号或绑定键、币种、网络、金额与最终状态。不要把“已检测”当成“已完成”；共享固定金额订单和实际到账的会员充值使用各自正确的金额口径。

无法确认时保留待处理状态，通过[订单查询](https://open.uugate.com/developers/query-payin-order.html)或人工核对解决，不把不确定状态写成成功，也不要按浏览器回跳结果发货。

## 4. 在一个数据库事务中处理业务

下面是处理顺序说明，不是数据库可执行 SQL：

```text
验证签名、时间窗口和请求格式
查找原始订单并核对商户、网络、币种、金额与状态
开始事务
  锁定业务订单或使用唯一约束防止重复交付
  如果已完成：读取已保存的处理结果
  否则：更新业务订单并写入可审计的入账/交付记录
提交事务
成功后返回平台要求的 2xx 应答
```

如果还需发邮件或调用第三方服务，将待执行工作以可靠队列或事务 outbox 记录下来；让外部动作也具备重试与去重能力。

## 5. 用失败场景验收

| 场景 | 应验证的结果 |
| --- | --- |
| 修改 JSON 空格或字段顺序后仍沿用旧签名 | 验签失败 |
| 修改金额或使用错误 API Key | 验签失败 |
| 同一订单重复通知 | 不重复入账或交付 |
| 写库成功但网络应答丢失 | 重试返回既有结果，不重复处理 |
| API Key 已轮换，旧订单仍未结束 | 能按原订单找到正确验签凭据 |
| 仅收到检测中/确认中状态 | 不提前宣布业务完成 |

需要排查具体问题时，先使用[未到账、过期与回调失败指南](https://cus.uugate.com/tutorials?article=troubleshooting&lang=zh-CN)整理脱敏信息，再通过[官方支持入口](https://uugate.com/contact/)联系支持。
